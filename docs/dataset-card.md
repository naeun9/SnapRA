## 1. 공개 범위 — 설명서 226,000 vs 실측 203,400

설명서는 총 226,000장이라고 적고 있으나 **공개 배포되는 것은 203,400장**이다.
AI-Hub 표준 8:1:1 분할에서 Test 10%가 비공개이기 때문이다.

| 분할 | 종당 | 총계 | 공개 |
| --- | --- | --- | --- |
| Training | 1,600 | 180,800 | O |
| Validation | 200 | 22,600 | O |
| Test | 200 | 22,600 | **X (비공개)** |
| 계 | 2,000 | 226,000 | 203,400 (90%) |

113종 전부 예외 없이 1,800장(= 1,600 + 200)이었고, 203,400 = 226,000 × 0.9 로 정확히
맞는다. 파일 트리에도 Training / Validation 디렉터리만 있고 Test는 없다.

**검증:** 설명서 값에서 실측값을 뺀 잔차가 서로 다른 축에서 모두 22,600으로 닫힌다.

| 축 | 잔차 합 |
| --- | --- |
| 실내(7,214) + 실외(15,386) | **22,600** |
| 맑음(14,571) + 흐림(6,067) + 비(1,962) | **22,600** |

우연히 맞을 수 없는 일치이므로, "설명서 = 구축 총량, 실측 = 공개분, 차이 = 비공개
Test 분할"이라는 해석은 확정적이다. 이후 모든 표의 기준은 **공개분 203,400**이다.

## 3. 시나리오 구성

### 3-1. Y/N 쌍 구조 (각 50종)

같은 번호의 Y와 N이 **동일 작업을 안전/불량 상태로 각각 촬영한 대조쌍**이다.
정답 라벨이 쌍으로 주어지므로 VLM의 정상·비정상 판정 정확도를 직접 측정할 수 있다.

| 예시 | 정상 (Y) | 비정상 (N) |
| --- | --- | --- |
| 03 | 개구부 덮개 설치 | 개구부 덮개 설치 불량 |
| 02 | 개폐형 발판이 닫혀 있는 상황 | 개폐형 발판이 열려 있는 상황 |
| 41 | 동바리 버팀 장치 설치 | 동바리 버팀 장치 설치 불량 |

50쌍 모두 1,800 : 1,800으로 완전 균형이다. 평가 지표가 클래스 불균형에 흔들리지 않는다.

## 6. 휴대폰 촬영 서브셋 — 실사용 조건 평가셋 근거

SnapRA의 입력은 **현장 작업자가 휴대폰으로 찍은 사진**이다. 드론·CCTV 시점에서 맞는
프롬프트가 휴대폰 사진에서도 맞는다는 보장이 없으므로, 휴대폰 촬영분을 따로 평가한다.

| | 전체 공개분 | Validation |
| --- | --- | --- |
| 총 장수 | 203,400 | 22,600 |
| 휴대폰(device=4) | **40,503 (19.91%)** | **3,426 (15.16%)** |
| 휴대폰이 존재하는 시나리오 | 53 / 113 종 | **25 / 113 종** |
| 종당 휴대폰 장수 | — | 최소 28 / 중위 156 / 최대 200 |
| 계열 구성 (Validation) | — | Y 1,710 / N 1,688 / C 28 / G 0 |

**한계를 명시해야 한다.** 휴대폰 촬영분은 전체 시나리오의 절반(53/113종)에만 존재하고,
Validation에서는 **25종 3,426장**으로 더 좁아진다. 안전보조장비(G) 계열에는 휴대폰
촬영분이 아예 **0장**이다. 따라서 휴대폰 평가셋은 **전 시나리오 커버리지를 주장할 수 없고**,
해당 25종 안에서의 실사용 조건 성능만 말할 수 있다. 전 시나리오 성능은 고프로 중심의 주
평가셋으로 보고, 휴대폰 서브셋은 "시점·화질이 바뀌어도 판정이 유지되는가"를 보는 보조
지표로 쓴다.

## 7. 공식 베이스라인

구축 사업에서 제시한 성능이다. 우리 접근(VLM 프롬프팅, 학습 없음)과 직접 비교 대상은
아니지만, 이 데이터에서 지도학습이 도달한 수준의 기준점이 된다.

| 과제 | 지표 | 모델 | 학습 환경 |
| --- | --- | --- | --- |
| 위험상황 탐지 | mAP **79.6%** | SpineNet 기반 Mask R-CNN | RTX 3090 × 4 |
| 객체 탐지 | mAP **78.3%** | SpineNet 기반 Mask R-CNN | RTX 3090 × 4 |

우리는 mAP가 아니라 **시나리오 단위 정상/비정상 판정 정확도**를 측정한다. 지표가 다르므로
숫자를 나란히 놓고 우열을 말할 수는 없다. 베이스라인은 "GPU 4장으로 학습한 모델이 있는
데이터"라는 맥락 제시용이다.

## 8. 데이터 성격과 한계

**시나리오 기반 계획 촬영이다. 실제 사고 장면이 아니다.** 안전 관리자가 지정한 113개
상황을 연출해 촬영한 것으로, 다음 한계를 발표에서 밝혀야 한다.

1. **연출된 장면** — 실제 사고 순간의 급박함, 가려짐, 흔들림이 재현되지 않았다.
   실제 현장 사진에서의 성능은 이 데이터로 측정한 값보다 낮을 수 있다.
2. **24개 현장** — 지역·공법·현장 규모가 제한적이다. 소규모 현장(우리 목표 사용자)
   비중은 알 수 없다.
3. **조건 편향** — 맑음 74.9%, 눈 0장, 캠코더 36장. 악천후·야간 성능은 검증 불가.
4. **고프로 중심** — 78%가 고프로다. 작업자 시점(헬멧 장착)이 많아 휴대폰으로 찍은
   일반적인 구도와 다르다.
5. **일반화 검증 별도 필요** — 이 데이터의 정확도는 "113개 정의된 상황을 구분하는 능력"이고,
   현장에서 마주칠 미정의 위험요인 탐지 능력은 측정되지 않는다.

### 8-1. 평가 설계에 반영해야 할 한계 (실측으로 확인된 것)

아래 네 항목은 추측이 아니라 라벨 203,400건을 센 결과다. 평가 결과를 해석할 때 그대로
같이 적어야 한다.

**(1) 휴대폰 서브셋이 좁다 — Validation 25종 3,426장**
전체 공개분에서는 53종에 걸쳐 40,503장이지만, 평가에 쓸 Validation 분할로 좁히면 25종
3,426장이다. 안전보조장비(G) 계열은 0장이다. 25종을 넘는 커버리지는 주장할 수 없다.

**(2) 화재(D) 휴대폰 438장 — 실사용 조건에서 평가 불가**
5대 사고유형 중 화재만 휴대폰 촬영분이 438장으로, 다른 유형의 1/10~1/50 수준이다.
실사용 조건 지표에서 화재는 제외하거나 "표본 부족"을 명시한다.

**(3) `object_pairs` 정상/비정상 비대칭 — 3~20배**
안전상태가 클래스명에 들어간 11쌍에서, 정상 클래스는 여러 시나리오에 배경으로 등장하는
반면 비정상 클래스는 해당 시나리오에만 나온다. 예를 들어 `SO-03 정상 작업발판` 37,227개
대 `SO-04 비정상 작업발판` 1,800개로 20.7배다. 객체 단위로 채점하면 "정상"을 남발하는
모델이 유리해지므로, **시나리오 단위 채점을 기본으로 하고 객체 단위 지표를 쓸 때는
클래스 가중치나 균형 표본으로 보정**해야 한다.

| 쌍 | 정상 | 비정상 | 배수 |
| --- | --- | --- | --- |
| 작업발판 상태 | SO-03 37,227 | SO-04 1,800 | 20.7× |
| 오거크레인 전도방지대 | WO-20 5,400 | WO-21 1,800 | 3.0× |
| 이동식 비계 안전난간 | WO-04 5,380 | WO-05 1,800 | 3.0× |
| 콘크리트 펌프카 전도방지대 | WO-12 5,327 | WO-13 1,800 | 3.0× |
| 시저형 고소작업대 과상승방지봉 | WO-10 5,453 | WO-09 1,867 | 2.9× |

**(4) 날씨 분포가 설명서와 다르다 — Test 분할이 조건별 균등 표본이 아님**
공개분 실측은 맑음 74.85% / 흐림 20.86% / 비 4.28%인데, 설명서 값을 90% 환산한
기대치(73.8% / 21.5% / 4.7%)와 최대 9.3% 어긋난다. 역산한 비공개 Test 22,600장은
**맑음 64.5% / 흐림 26.8% / 비 8.7%**로 악천후 비중이 뚜렷하게 높다. 즉 비·흐림 촬영분이
Test 쪽에 더 많이 배정됐다. 공개분만으로 악천후 성능을 말하면 실제보다 낙관적으로 나올
수 있고, 눈(4)은 애초에 0장이다.
